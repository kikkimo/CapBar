# CapBar 方案记录

## 账号与设置

- Claude Code 和 Codex 的默认配置目录首次自动加入；用户可以追加或移除任意目录，包括默认目录。移除的默认目录不会在下次启动时重新加入。
- 邮箱、组织和套餐由账号识别，不设置“个人”“工作”等手填名称。
- 用户设置只有账号目录、“打开弹窗时自动刷新”开关和共用的刷新阈值。开关默认关闭，阈值默认 5 分钟。
- 没有后台定时刷新。开关关闭时，打开弹窗只显示已保存快照；开启时，每次打开只刷新距该账号上次探测达到阈值的账号。

## 刷新与快照

- “全部刷新”始终可点，会刷新所有空闲账号，跳过正在刷新的账号；单账号按钮只在该账号未刷新时启用。手动刷新不受阈值限制。
- 刷新中保留旧额度与采集时间，并显示动态 loading。关闭弹窗不会取消任务；再次打开时显示进行中或已完成的结果。
- 每个账号独立保存快照和时间。建议使用 `~/Library/Application Support/CapBar/snapshots.json`，以“服务类型＋规范化配置目录”为键，串行、原子写入；不保存令牌或原始会话内容。
- `capturedAt` 是上次成功采集额度的时间；`lastAttemptAt` 是上次探测尝试时间。自动刷新阈值根据后者判断，失败后在阈值内不自动重试，但手动刷新始终可重试。
- 采集时间在 3 分钟内显示“刚刚”，60 分钟内显示“X 分钟前”，之后显示具体日期和时间。失败保留旧额度与原采集时间，并标记失败。

## 数据获取

Claude 每个账号每次刷新只进行一次受限交互对话：

1. 在该账号的配置目录下启动受限交互会话，发送一条最小提示词。
2. 收到回复及该次会话产生的 statusline 数据。
3. 查询该账号的 OAuth 用量接口。
4. 比较有效数据的采集时间，选择用于界面展示的结果；界面只显示一组额度。只有一条渠道有效时使用它。
5. 发送 `/exit`，等待进程正常退出；超时则终止进程。

本机实测 `claude -p` 能回复但不触发 statusline；受限交互会话在回复后产生 statusline，发送 `/exit` 后可以退出。Codex 直接调用 app-server 的 `account/rateLimits/read`，不发最小对话。

## 失败与重试

- 每账号最多尝试 3 次，含首次；每次限时在 30–60 秒内，重试前随机等待 10–20 秒。三次均失败才将该账号标记为失败。
- 只重试网络中断、超时等暂时性错误；认证失效、目录无效等确定性错误立即失败。Claude 的 statusline 或 OAuth 任一渠道返回有效额度，即视为成功，不为补齐另一渠道而再次发起对话。
- 尝试次数、超时和随机等待范围属于开发／打包配置，放在随源码管理的配置文件中，由构建产物读取；不出现在用户设置界面，也不写死在刷新逻辑里。
