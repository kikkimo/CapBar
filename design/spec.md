# CapBar v1 产品与工程规格

**状态：** 已对齐的 v1 规格。视觉基准为 [capbar-visual-study.html](capbar-visual-study.html)，讨论记录见 [plan.md](plan.md)。

## 目标与范围

CapBar 是 macOS 菜单栏应用，在一个弹窗中查看多个 Claude Code、Codex 配置目录对应账号的剩余额度、重置时间和采集时间。v1 提供手动刷新及可选的“打开弹窗时按需刷新”。应用不在后台定时探测，不发送消息、修改用户项目，亦不管理登录或消费额度重置权益。

本机开发环境为 Apple Silicon、Swift 6.3 命令行工具；没有完整 Xcode。v1 使用 Swift Package Manager 构建并由打包脚本形成 `.app`。目标平台为 macOS 14 或更新版本；首个交付物为本机可运行的 Apple Silicon 应用。图标可以在应用功能完成后替换，不阻塞架构和测试。

## 账号身份与配置

| 项目 | v1 行为 |
| --- | --- |
| 账号键 | 服务类型＋规范化配置目录；邮箱变化不会生成新账号键。 |
| 默认目录 | 首次运行加入 `~/.claude`、`~/.codex`；之后以用户保存的列表为准。 |
| 自定义目录 | 可分别添加多个 Claude 和 Codex 目录，也可移除任意目录，包括默认目录。 |
| 身份 | Claude 读取邮箱、套餐、组织；Codex 读取可用的邮箱、套餐信息。无法识别的字段不虚构。 |
| 用户设置 | 账号目录列表；“打开弹窗时自动刷新”开关，默认关；共用刷新阈值，默认 5 分钟；弹窗宽、高，最小 448 × 620 pt；“登录时自动启动”系统登录项开关，默认关。 |
| 内部打包配置 | 最大尝试次数、单次超时、重试等待下限／上限；不出现在用户设置界面。 |

Claude 默认目录运行 CLI 时必须**不设置** `CLAUDE_CONFIG_DIR`；非默认目录设置为规范化绝对路径。本机实测默认目录的钥匙串服务名为 `Claude Code-credentials`，自定义目录为 `Claude Code-credentials-` 加规范化绝对路径 SHA-256 的前 8 位十六进制字符。先前四个目录的 OAuth 实测确实通过 `/usr/bin/security find-generic-password` 读取相应服务的令牌，再请求用量接口；它没有弹授权窗，但仍属于钥匙串访问。CapBar 仅在查询该账号 OAuth 额度时执行同一命令，设定超时；开发测试使用假命令，不读取真实凭据。Codex 为每个目录使用相应的 `CODEX_HOME`。识别账号身份不应发起 LLM 对话。

## 数据模型与持久化

每个账号保存一个记录：账号键、识别出的身份、各额度窗口、`capturedAt`、`lastAttemptAt` 和最近一次失败类别／时间。`capturedAt` 是成功取得额度的采集时间；`lastAttemptAt` 是最近一次探测开始时间，即使最终失败也保留。额度窗口分别存储窗口类型、**剩余百分比**和重置绝对时间；不存在的窗口不存储、不显示。百分比必须验证为有限数并限制到 0–100；时间使用 UTC 绝对值存储，显示时转为本机时间。

用户设置与快照分别存在 `~/Library/Application Support/CapBar/settings.json`、`snapshots.json`。写入先完成完整编码，再以原子替换落盘，避免多个账号并发完成时丢失记录；文件权限限制为当前用户读写。文件包含 schema 版本。刷新中状态只存在内存，应用重新启动后不会误显示为仍在运行。不得把 OAuth token、Keychain 内容、原始 statusline／OAuth 响应或会话文本写进上述文件或日志。

登录时自动启动由 macOS 的登录项状态管理，不在 `settings.json` 中重复存储。只有从 `/Applications/CapBar.app` 运行的正式安装版本可注册；构建目录中的临时版本不能注册。开启后只启动菜单栏应用，不主动探测额度。系统要求批准时，设置页显示状态并提供打开“登录项”设置的入口。

## 刷新触发与状态

账号状态为无快照、已有快照、刷新中、失败后保留旧快照，以及失败且无快照。每个账号独立运行；一个账号失败不阻塞其他账号。

| 触发 | 行为 |
| --- | --- |
| 打开弹窗且开关关闭 | 立即显示已有快照；不探测。 |
| 打开弹窗且开关开启 | 分别比较每个账号的当前时间与 `lastAttemptAt`；达到共用阈值的空闲账号才探测。没有 `lastAttemptAt` 的账号视为到期。 |
| 手动单账号刷新 | 该账号空闲时立即探测，不受阈值限制；探测中按钮禁用。 |
| 手动全部刷新 | 按钮始终可点，向所有空闲账号发起探测，直接跳过已在探测的账号；不排队重复任务。 |
| 弹窗关闭 | 已开始的探测与重试继续，完成后写入快照。再次打开显示实时状态或结果。 |

探测开始即记录 `lastAttemptAt`。失败后，阈值内重复打开弹窗不自动重试；用户随时可手动重试。刷新中保留旧额度和旧 `capturedAt`，显示动态 loading。成功后原子更新该账号快照并清除错误；失败则保留旧快照及其采集时间，并显示失败状态。没有旧快照时显示“暂无额度快照”及失败原因。刷新不改变其他账号记录。

## Claude Code 探测

一次**尝试**在该账号配置环境中启动受限交互会话，只发送一条最小提示词。进程使用应用自己的临时工作目录和临时 statusline 捕获设置，禁用工具及 MCP，不能读取或修改用户项目。收到回复后在限定时间内收集本次 statusline；即使 statusline 未产生，也继续查询该账号的 OAuth 用量接口，以保留单渠道 fallback。随后发送 `/exit` 并等待正常退出。超时或无法正常退出时终止进程并清理临时资源。默认目录使用系统默认凭据映射，非默认目录使用对应配置目录的凭据映射。OAuth 查询通过上述限时 `security` 命令取得令牌；查询失败时仍使用本次有效的 statusline。令牌只在内存中用于读取用量，不持久化、不打印。

statusline 与 OAuth 结果分别解析为可选的 5 小时和 7 天窗口，记录本机收到有效结果的时间。对同一窗口同时有两条有效结果时选采集时间较晚的一条；仅有一条时使用它。两条结果可在内部比较，但界面每窗口只显示一个值。某窗口在两条渠道都缺失时不显示。两条渠道都没有有效额度才算本次尝试失败；一条成功就不为补齐另一条而再次发起对话。`claude -p` 不用于该流程，因为本机实测它不触发 statusline。

## Codex 探测

在相应 Codex 配置目录下启动只读 app-server，调用 `account/read` 识别账号，并用 `account/rateLimits/read` 获取额度。不发送最小对话。根据响应的 `windowDurationMins` 识别窗口，不依赖 `primary`／`secondary` 固定位置；优先使用 `rateLimitsByLimitId` 中的 Codex 限额桶，缺失时使用兼容视图。只有 7 天窗口的账号仅显示 7 天。没有有效窗口时报告失败，不编造 5 小时数值。

## 重试与进程收尾

每账号最多 3 次尝试，含首次；每次尝试的超时在 30–60 秒内，重试前随机等待 10–20 秒。网络中断、请求超时、进程异常退出等暂时性故障可重试。目录不存在、未登录、认证失效或明确的无权限响应立即失败。已取得一条有效 Claude 渠道结果即成功，不触发额外尝试。重试参数由打包时提供的 `ProbePolicy.json` 读取并校验；用户无法在设置界面修改。任何路径结束后都要退出或终止子进程，不留下后台 Claude/Codex 进程。

## 界面与时间文案

界面按已确认 HTML 实现：菜单栏摘要、账号分组、邮箱主标识、组织／套餐／目录辅助信息、独立的 5 小时与 7 天额度及重置时间、全局与单账号刷新、设置页。系统浅色／深色材质可随 macOS 渲染，信息层级、间距、状态表达和交互位置以 HTML 为基准。

弹窗宽高由用户设置保存，可输入精确数值并在提交后调整窗口；上下按钮以 10 pt 为步进，增宽到 640 pt 时账号行改为横向布局。窗口背景使用半透明系统材质。普通交互中弹窗失去焦点或点击外部自动关闭；打开目录选择器期间暂时保持弹窗，选择或取消后恢复自动关闭，且停留在设置页。

每个账号独立显示 `capturedAt`：不超过 3 分钟显示“刚刚”；超过 3 分钟但未满 60 分钟显示“X 分钟前”；满 60 分钟显示具体本地日期和时间，跨年时包含年份。相对时间文案可以由轻量 UI 时钟更新，**不得借此触发额度探测**。加载中保留旧数值并显示 spinner，单账号按钮禁用；全局按钮保持可点。失败、无快照、只有单个额度窗口等状态与 HTML 对照一致。

采集时间以时钟图标和较醒目的色块显示。刚刚为绿；显示 10 分钟以内、30 分钟以内、60 分钟以内以及具体时间时，颜色依次向红过渡。没有快照时使用中性色，不暗示已有新数据。

## 验收场景

1. 首次启动默认目录进入列表；移除默认目录并重启后不再自动出现。添加两个不同配置目录可分别识别身份与快照。
2. 默认关闭打开时自动刷新。打开、关闭、重复打开弹窗均不发起探测；手动单账号与全部刷新按各自规则运行。
3. 开启打开时自动刷新后，每个账号独立按共用 5 分钟阈值判断；一个账号刚刷新过不影响其他过期账号。失败的账号在阈值内不自动重试，手动刷新仍可执行。
4. 同一账号只允许一个探测任务。单账号按钮在其运行期间禁用；全局按钮可重复点击但不为该账号排队。关闭弹窗不取消任务。
5. Claude 对话收到 statusline 后查 OAuth，再发送 `/exit`；两渠道均有效时只显示时间较新的每窗口结果，只有一条有效时使用它。无效窗口不显示。
6. Codex 仅读 app-server；响应只有 7 天窗口时，界面不显示 5 小时窗口。
7. 暂时性错误最多尝试 3 次，重试间隔在 10–20 秒；认证与目录错误不重试。全部失败时保留旧快照和原采集时间并显示错误。
8. `capturedAt` 在 3 分钟、60 分钟边界正确切换文案；刷新中旧值仍可读，成功后更新时间，失败后不篡改成功采集时间。
9. 本机 SwiftPM 测试通过、可构建并启动 `.app`；进程超时和应用退出时没有遗留子进程；本地 JSON 和日志无凭据。
10. 宽高调节立即生效且重启后保留；只有文件夹选择器打开期间暂停失焦关闭，其他操作失焦自动收起。
11. 登录时启动默认关闭，正式安装版本可开启或关闭；临时构建版本无法注册；需要系统批准时有明确提示。
